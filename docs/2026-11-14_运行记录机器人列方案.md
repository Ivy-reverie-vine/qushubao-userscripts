# 任务运行记录页 · 「机器人」自定义列方案（Spec）

日期：2026-11-14  
目标页：`https://dep.ai-indeed.com/mallQuan/taskExecuteManagementV2`（计划视图）  
载体：`qushubao-userscripts.user.js`（接入 `taskExecute` 页面模块与现有 `/job/record/new` 响应钩子，严格遵守 `@grant none`、零依赖与雪花 ID 字符串约定）

---

## Problem Statement

在「计划中心 -> 运行记录」页面的计划视图中，平台原生表格与「自定义字段」面板仅提供计划名称、店铺、最近运行起止时间、取数执行、采集文件校验、数据入库、数据校验及操作列，缺少「机器人」列。当多个任务计划未在名称中显式标明机器人编号、或计划后续改绑了机器人时，运维人员无法在运行记录列表页直接识别每条日任务记录所属的机器人，也无法按自己的阅读习惯将该列嵌入现有列序中显示或隐藏。

## Solution

在现有 `taskExecute` 页面模块中扩展「当前绑定机器人」列能力：

1. **按需补数**：在启用「机器人」列时，通过平台计划列表接口分批拉取当前租户全量计划的机器人展示名映射，按计划身份关联到表格行；未启用（默认隐藏）时不产生额外列表请求。
2. **自定义字段弹窗无缝融合**：监听「操作 ⚙ -> 自定义字段」面板打开，注入风格一致的「机器人」字段项，支持复选框自由显示/隐藏、手柄指针拖拽调序（插入任意非固定原生字段之间）、联动「恢复默认」，并将配置持久化到本地存储。
3. **相对锚点同步渲染**：以「参照列标题 + 前/后侧」记录位置而非写死列下标，在表格 `<colgroup>`、表头、测量行与数据行四处同步插删该列，确保在用户拖拽或开关原生列、切换分页与日期后，既有店铺筛选与异常气泡仍精准命中各自目标列。

## User Stories

1. As an 运维人员, I want 「机器人」列在首次使用脚本时默认处于隐藏状态, so that 页面原有列布局与网络请求不受打扰。
2. As an 运维人员, I want 在「操作 ⚙ -> 自定义字段」弹窗里看到与其他字段外观一致的「机器人」选项, so that 我能用熟悉的入口控制该列。
3. As an 运维人员, I want 勾选或取消勾选弹窗内的「机器人」复选框, so that 我可以随时开启或关闭运行记录表中的「机器人」列。
4. As an 运维人员, I want 当「机器人」列保持隐藏时脚本不主动请求计划列表接口, so that 不产生无用的接口开销。
5. As an 运维人员, I want 在勾选开启「机器人」列后立即显示当前页每条日任务记录对应的当前绑定机器人名称, so that 不用逐条点进计划详情就能分辨所属机器人。
6. As an 运维人员, I want 拖拽弹窗内「机器人」项右侧的手柄把它移动到任意非固定字段之前或之后, so that 「机器人」列能贴近「计划名称」或「店铺」等我最关注的列展示。
7. As an 运维人员, I want 拖拽「机器人」项时看到清晰的落位提示并且无法拖到「操作」固定列之后, so that 排列反馈直观且符合右侧固定操作列的约束。
8. As an 运维人员, I want 刷新页面、翻页或切换上方日期后，脚本记住我设置的「机器人」列显隐状态与相对位置, so that 不用每次重新配置。
9. As an 运维人员, I want 我通过原生设置隐藏或重排了某几个原生列后，已开启的「机器人」列依然稳定显示在设定的相对位置（参照列被隐藏时有合理的相邻回退）, so that 表格不会缺列或错位。
10. As an 运维人员, I want 点击弹窗内的「恢复默认」后，「机器人」列同步恢复为隐藏且重置默认位置, so that 我能一键回到干净的初始视图。
11. As an 运维人员, I want 同时包含日常计划与回溯任务的运行记录都能匹配到各自当前的绑定机器人, so that 回溯任务不会无故缺失机器人展示。
12. As an 运维人员, I want 遇到已删除计划或未返回机器人名称的记录时单元格显示占位符 `-`（多机器人计划按列表值如实展示）, so that 表格对齐不被破坏且不伪造数据。
13. As an 运维人员, I want 开启「机器人」列（即使插在「店铺」或「取数执行」前面）后，顶部的店铺名称过滤/高亮以及「取数执行」列上的异常色球和悬停浮层依然精准工作, so that 现有增强功能零退化。
14. As an 运维人员, I want 表格在固定布局下插入「机器人」列时表头、数据单元格与右侧固定「操作」列保持对齐，超长机器人名省略显示并有完整悬浮提示, so that 页面视觉不崩坏。
15. As an 运维人员, I want 切换到站内其他页面离开运行记录页时，脚本注入的弹窗项、表格列与拖拽监听全部被清理干净, so that 不会污染其他路由或造成内存泄漏。

## Implementation Decisions

- **数据来源与口径（方案 A）**
  - 日任务记录主接口（`job/record/new`）、订单详情（`job/record/detail/new`）、工作列表（`job/record/work/list`）及流程块结果（`work/result/new`）均不返回机器人信息。
  - 统一通过 `POST /opt/qymall/1.0.0/schedule/page` 补数：请求体携带 `jobType: ""` 以同时覆盖日常计划与回溯任务，按分页元数据完整拉取并遵守统一请求间隔（`>= 200ms`）。
  - 展示口径明确为**当前绑定机器人**（来自列表的 `botName`），不冒充历史执行态机器人；匹配优先级为日记录 `planId` 对齐列表 `id`，次选 `jobUuid` 对齐，所有 ID 保持字符串比较。
  - 映射结果在页面生命周期内内存缓存，仅在「机器人」列开启且尚无可用缓存时发起拉取；未匹配到或 `botName` 为空时显示 `-`。
- **配置持久化与相对锚点模型**
  - 使用 `localStorage` 存储用户偏好（符合 `@grant none` 约束），核心字段包括：
    - `visible`: 布尔值，默认 `false`（默认隐藏）。
    - `anchor`: `{ key: string, side: 'before' | 'after' }`，默认 `{ key: 'storeName', side: 'after' }`（默认位置紧跟「店铺」之后；若「店铺」不可见，按邻近回退链最终落位在「操作」列之前）。
  - 拖拽排序时不写入固定数字索引，而是根据落位后相邻的原生 `data-rbd-draggable-id`（及表头标题映射）更新 `anchor`；原生列拖拽调序时，脚本可依 `anchor` 将弹窗项与表格列维持在参照列旁。
- **自定义字段弹窗的融合与指针拖拽**
  - 不为「机器人」项声明原生 `data-rbd-draggable-id` 或接入 `react-beautiful-dnd` 上下文，避免 React 受控列表重绘冲突与运行时索引异常。
  - 监听自定义字段列表容器出现后，按当前 `anchor` 插入复用原生行样式的「机器人」配置行，内置标准样式复选框与拖动手柄。
  - 手柄拖拽基于原生 Pointer 事件（`pointerdown` / `pointermove` / `pointerup`）计算指针相对原生可拖拽项中线的位置，显示插入指示线并限定不可越过固定在最末的「操作」项；松手即更新 `anchor` 并重排表格列。
  - 监听面板内「恢复默认」按钮点击，同步将机器人列复位为隐藏与默认 `anchor`。
- **单表格四处同步插列与既有能力隔离**
  - 运行记录计划视图为单 `<table>`（`table-layout: fixed`）配合右侧 `sticky` 操作列，不存在双表拆离。
  - 插入或移除「机器人」列时，按锚点表头计算目标列下标，在 `<colgroup>`、`<thead> tr`、`.ant-table-measure-row` 与每行 `tr.ant-table-row` 四处原子同步插删，并按固定列宽（如 `110px`）同步增减 `<table>` 总宽度。
  - 所有表格与弹窗 DOM 改动均包裹内部变更锁并标记专用属性，被表格 `MutationObserver` 过滤以防自激死循环；每次列结构变更后主动清空既有店铺列与状态列索引缓存，保证按表头文本重新探测。
  - 当页面切换到非计划视图（无「计划名称」与「操作」目标表头）或离开 `taskExecute` 路由 `teardown` 时，完整撤销注入节点与事件监听。

## Testing Decisions

- **测试策略**：仅验证外部可观测行为（DOM 输出、存储状态、网络请求触发时机、既有筛选/异常展示行为），不耦合内部私有函数名或拖拽内部坐标变量。
- **测试接缝（Testing Seams）**
  - 复用 `tests/core.test.mjs` 的 `vm` 沙箱架构（带最小 DOM 桩、`localStorage` 桩、`fetch` 桩、拦截器与路由切换）：
    1. **路由与接口桩接缝**：进入 `/mallQuan/taskExecuteManagementV2`，注入 `/job/record/new` 响应及 `/schedule/page`（含多页、`jobType=1/2`、空 `botName`、19 位字符串 ID）模拟返回。
    2. **自定义字段弹窗与指针事件接缝**：模拟弹出 `task-execute-field-setting` 面板与原生项，触发复选框变更、手柄指针拖拽到不同原生项之间、以及点击「恢复默认」。
    3. **表格结构与跨功能联动接缝**：验证默认隐藏不发 `schedule/page` 请求；开启后仅请求一次并缓存；表格四处结构同步增删列且内容正确；「机器人」列插到「店铺」或「取数执行」之前时，店铺过滤高亮与状态列异常色球及 Tooltip 仍命中正确单元格；`teardown` 后无残留节点与监听。
- **既有参考**：`tests/core.test.mjs` 中已有的 `createEnv` / `makeTable` / `makeRow` 与路由回归用例。

## Out of Scope

- 不实现通过 `work/record/list` 拉取「历史实际执行机器人」（因全租户分页性能不可控）。
- 不支持多机器人计划拆分展示多个独立绑定标签或按 `job/detail` 逐行回查已删除计划。
- 不在本期增加机器人表头宽度拖拽持久化及顶部筛选栏「按机器人过滤」新控件。
- 不适配非计划视图（运行记录视图）的表头列注入。

## Further Notes

- 原生站点的自定义字段设置弹窗内部依赖 `react-beautiful-dnd`，若未来站点重构该弹窗类名或字段 `data-rbd-draggable-id` 命名，需同步更新弹窗识别锚点。
- 若后续需要新增顶部「按机器人过滤」或导出表格等功能，可直接复用本次沉淀的计划机器人映射缓存。
