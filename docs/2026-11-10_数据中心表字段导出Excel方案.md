# 数据中心 · 表字段导出 Excel 方案

日期：2026-11-10
目标页：`https://dep.ai-indeed.com/mallQuan/dataCenter`
载体：`qushubao-userscripts.user.js`（原 `qsb-taskexecute-helper.user.js`，新增一个页面模块，不新增文件、不引入依赖）
导出格式参考：`D:/Desktop/租户名ETL映射表YYYY-HH-MM.xlsx`

## 一、结论

**能做，且不需要新依赖。** 三块能力各自独立可验证，拼起来即可：

| 块 | 内容 | 状态 |
| --- | --- | --- |
| ① 数据源 | `POST /conn/mapper/get` 按连接器取全部表的字段定义 | 文档已有真实只读证据，字段齐全 |
| ② 列注入 | 在展开行的嵌套表里插入「导出Excel」列（第 3 列） | 标准 DOM 操作，Ant Table 重渲染需补插 |
| ③ 浏览器端生成 xlsx | 手写 ZIP + 最小 OOXML，`@grant none` 下直接下载 | **已在本机跑通并校验**，见第六节 |

唯一没有现成证据的是「外层行 `data-row-key` 是否就是 `conn/mapper/get` 要的 `connectorId`」。这一点**不阻塞**：方案里给了运行时双路兜底（第六节 4.2），不依赖推断。

## 二、参考文件逆向出的导出规约

参考文件 `租户名ETL映射表YYYY-HH-MM.xlsx` 实测（openpyxl 只读解析）：

- 共 **36 个 sheet**，一个 sheet 承载 1~N 张表的字段块。
- 每个表块固定 4 行 + N 行字段：

```
R1  连接器名称：{connectorName}        ← 合并 A:D，宋体 12
R2  中文表名：{tableNameCn}            ← 合并 A:D，宋体 12
R3  英文表名：{tableNameEn}            ← 合并 A:D，宋体 12
R4  字段英文名 | 字段中文名 | 数据类型 | 长度   ← 宋体 11，加粗
R5+ {fieldName} | {fieldComment} | {fieldAttr} | {fieldLength}   ← 宋体 11
```

- 列宽：A 列 17.78，B/C/D 默认；**无冻结窗格**，表头无填充色，只有 R4 加粗。

> 与参考文件的两处有意偏差（2026-11-10 追加）：R1~R3 三行标题加浅蓝底色 `FFDDEBF7`（参考文件里是纯白，三行标题贴着字段表，肉眼分不清块边界）；B/C/D 列给了显式宽度（22/30/12/10），参考文件是默认宽度，字段中文名会被截断。
- 数据类型实测分布：`varchar` 1648、`int` 898、`decimal` 802、`datetime` 168、`bigint` 2。
- 长度取值形态：空、`-`、`10/20/25/50/100/255/256/258/1024/2048`、`16,4 / 20,8 / 28,4`（精度型两段式，**必须按字符串写**，拆成数字会丢精度语义）。

参考文件本身有几处人工复制留下的错误，正好说明这份数据不该靠手抄：

- sheet「电商罗盘-直播列表直播间明细全部」的 R1 写成了「连接器名称：电商罗盘-商品列表商品列表」；
- sheet「生意参谋(旧版)-品类品类360标准类目」的 R1 也串成了小红书千帆的连接器名；
- `sycm_category_commodity_rank`、`dslp_live_product_details` 两个英文表名各出现两次（分属不同连接器，本身合法）。
- sheet 名与 R2 中文表名不完全一致（如 sheet「电商罗盘-直播列表直播间明细全部」 vs 中文表名「电商罗盘-直播列表直播间明细下载」），最长的 sheet 名 30 字符，已贴 Excel 的 31 字符上限。

**导出以接口返回为准，R1/R2/R3 三行全部由接口字段生成**，不读页面文本、不复制。

## 三、数据从哪来

### 3.1 主接口

```
POST /frameWorkPortal/opt/qymall/1.0.0/conn/mapper/get
Body: {"connectorId": "1733075975150305281"}
```

响应 `code === "10000"`，`bizData` 是**数组**（不是分页对象），每项一张表：

| 字段 | 用途 |
| --- | --- |
| `tableNameCn` | Excel R2 |
| `tableNameEn` | Excel R3，同时作为行匹配键 |
| `fields[]` | 字段行，见下 |

`fields[]` 每项：`fieldName`（R 列 1）、`fieldComment`（R 列 2）、`fieldAttr`（R 列 3）、`fieldLength`（R 列 4），另有 `validStatus`、`fieldLock`。

**必须遵守的两条语义**（文档已明确、且踩过坑）：

1. `validStatus=0` 表示**没有标准映射**，字段仍正常使用 —— 不过滤、不标异常。
2. `fieldLock=1` 只表示中英文名和类型被锁定不可改 —— 与导出无关，不参与判断。

导出全量字段，不做任何过滤。真实样例：某连接器 3 张表共 1377 字段，单表最多 1131 字段 —— 这个量级必须进方案（见 6.3 体积）。

### 3.2 长 ID 精度

`connectorId`、表 `id` 是 19 位雪花号，超过 `Number.MAX_SAFE_INTEGER`。**全程按字符串传**，禁止 `parseInt` / `Number()` / 数字参与 JSON。这一点参考文档已单独警告过。

### 3.3 兜底接口

```
POST /frameWorkPortal/opt/qymall/1.0.0/connector/page
Body: {"pageSize":20,"pageNo":1,"connectorName":"<完整连接器名>",
       "publishStatus":"","bizParamType":"","tagIds":[],"industryProducts":"1"}
```

`records[].id` 即 connectorId，但**必须对 `connectorName` 做完全一致匹配** —— 该接口是模糊搜索，会返回多个相似名（如「…商品(自选指标)」会混进来）。

## 四、交互与 DOM 注入

### 4.1 插入位置

展开行里的嵌套表是**单表结构**（`thead` 与 `tbody` 在同一个 `<table>` 内，非 fixed-header），因此表头和数据行可以一起改：

```
表中文名称 | 表英文名称 | [导出Excel] | 更新时间 | 清洗规则 | 映射规则 | 校验规则 | 操作 | 是否启用
```

- 列索引**按表头文字 `表英文名称` 反查**，不写死 `2`（站点调列序不炸）。
- 插入 `<th>导出Excel</th>` + 每行 `<td><button class="qsb-export-btn">导出Excel</button></td>`，插在 `表英文名称` 单元格之后。
- **必须同时补一个 `<col>`**：嵌套表是 `table-layout: auto`，`colgroup` 只有 6 个 `<col>` 却对应 9 个 `th`，插在 `表英文名称` 之后的那一列会白拿 20% 宽度、并把后面几列挤瘦。在 `colgroup` 第 2 个子元素后插一条 `width:96px` 的 `<col>`，后面各列的比例就回到原始值。样式表里另外给 `th/td[data-qsb-export]` 写了同样的 `96px` 兜底（colgroup 被 React 重建时仍有约束）。

### 4.2 取数链路（点按钮时）

```
点击 → 定位所在 tr 的 data-row-key（表 id）与中文/英文表名
     → 定位父行（上一行 tr.ant-table-row-level-0）的 data-row-key → 猜作 connectorId
     → conn/mapper/get(connectorId)
         ├─ 命中（按 tableNameEn 精确 → tableNameCn → 表 id）→ 生成 xlsx
         └─ 未命中 / bizData 空 / code≠10000
              → connector/page(connectorName 精确匹配) 取名 → conn/mapper/get 重试一次
                   └─ 仍失败 → 按钮旁红字「未取到字段定义」，控制台打原因
```

- `Map<connectorId, tables[]>` 会话内缓存：同一连接器下多张表只请求一次。
- 请求间隔复用现成的 `REQUEST_INTERVAL_MS = 200`。
- 请求复用现成的 `apiPost()`（已带 `Auth_token` + `credentials: same-origin`）。
- 不注册 `onResponse` 钩子 —— 该页列表接口未见于文档，方案不依赖它，主动请求即可。

### 4.3 抗重渲染

Ant Table 在以下时机会重建/更新行：展开折叠、切分页、筛选、切换「是否启用」开关、刷新。策略：

- 每次补齐前**先按标记去重**（`th[data-qsb-export]` / `td[data-qsb-export]`），有就跳过，不会重复插。
- `MutationObserver` 观察 table 容器（`childList + subtree`），300ms 防抖后补插，容器变化时重挂观察点。
- 脚本内已有的 `isSelfModifyingDOM` 自激保护沿用。
- 只增删自己的节点，**不改 React 管理的单元格内容**。

## 五、三种生成方式对比

| | A. 手写 xlsx（推荐） | B. SpreadsheetML 2003（.xls） | C. CSV(UTF-8 BOM) |
| --- | --- | --- | --- |
| 依赖 | 无（ZIP+CRC32 自写，约 130 行） | 无 | 无 |
| 多 sheet | 支持 | 支持 | 不支持 |
| 三行标题合并 / 加粗 / 列宽 | 支持 | 支持 | 不支持 |
| Excel 打开 | 原生无提示 | 常提示「格式与扩展名不匹配」 | 需另存，长数字易被转科学计数 |
| 体积（1131 字段） | 389 KB | 约 1.2 MB（纯 XML 无压缩） | 约 300 KB |
| 验证状态 | **已跑通** | 未验证 | — |

选 **A**。理由：参考文件是 `.xlsx`，A 的保真度最高，且不需要任何外部库 —— 与 AGENTS.md「单文件、`@grant none`、无依赖」完全一致。

## 六、xlsx 生成实现要点（已在本机验证）

### 6.1 文件结构

7 个部件，**不用 sharedStrings**（全部走 `t="inlineStr"`，省掉字符串表这一整层）：

```
[Content_Types].xml
_rels/.rels
xl/workbook.xml
xl/_rels/workbook.xml.rels
xl/styles.xml
xl/worksheets/sheet1.xml ... sheetN.xml
```

### 6.2 三个必须写对的点

1. **ZIP 用 STORE（method=0）**，不压缩。省掉 deflate 实现，只需在本地文件头和中央目录里写对 `crc32` 与 `compressedSize == uncompressedSize`。
2. **CRC32 必需**。标准多项式 `0xEDB88320`，256 项查表，约 10 行。
3. **XML 转义 + 长 ID 字符串化**。真实字段名里出现过尾部带双引号的 `wh_return_to_supplier_mtd"`，不转义直接破文件。

其余：`mergeCells` 写 R1/R2/R3 的 `A{n}:D{n}`；`styles.xml` 三个 `xf`（默认 / 宋体12 / 宋体11加粗），必须带 `<cellStyles><cellStyle name="Normal" builtinId="0"/></cellStyles>`，否则部分解析器报「缺少默认样式」；分页符与冻结窗格可选，参考文件本来就没有冻结。

### 6.3 实测数据

本机原型（Node 22，与浏览器 `TextEncoder`/`DataView` 同一套 API）：

| 场景 | 结果 |
| --- | --- |
| 1131 字段单表 | 398,851 字节 ≈ 389 KB，7 个部件 |
| 普通表（几十字段） | < 30 KB |
| openpyxl 读回 | sheet 名、`A1:D{n}` 合并、宋体12/宋体11、R4 加粗、字段逐行一致 |
| 特殊字符 `a<b>&"c"` | 原样往返，不破文件 |
| 样式告警 | 补 `cellStyles` 后 `python -W error` 零告警 |

原型留档：`C:/Users/77354/AppData/Local/Temp/qsb-xlsx-proto/proto.mjs`（仅验证用，不进仓库）。

### 6.4 下载与命名

```js
const url = URL.createObjectURL(new Blob([buf], { type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet' }));
const a = document.createElement('a');
a.href = url; a.download = fileName; a.click();
setTimeout(() => URL.revokeObjectURL(url), 10000);
```

- 单表导出文件名：`{中文表名}_{英文表名}.xlsx`
- sheet 名：中文表名，**截断到 31 字符**，去掉 `\ / ? * [ ] :`，重名追加 `_2`（参考文件最长 sheet 名 30 字符，已到边界）
- 文件名同样要过滤非法字符并限长（Windows 260 路径限制）

## 九、风险与退路

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 外层行 `data-row-key` 不是 `conn/mapper/get` 的 connectorId | 取不到字段 | 运行时双路兜底（4.2），`connector/page` 精确匹配兜底；两条都失败才报错 |
| 该页连接器名与 `/connector/page` 里的名字不完全一致 | 兜底也失败 | 报错时把两个名字都打日志；必要时改为「模糊搜索结果中人工选择」 |
| Ant Table 重渲染抹掉注入列 | 按钮消失 | MutationObserver 补插（4.3），已有成熟同款做法 |
| 新列挤压原表布局 | 视觉不齐 | 先靠 `auto` 布局；不行再补 `<col>`，不动 antd 的 `th` 样式 |
| 单连接器多表、字段上千 | 请求慢、文件大 | 按表懒加载 + 会话缓存；单表 389 KB 可接受 |
| `fieldAttr` 出现新类型 | 列值异常 | 原样输出，不做枚举校验 |

## 十、已确认（2026-11-10）

1. **导出粒度**：只做单表——点哪张表导哪张，一个文件一个 sheet。连接器级「导出全部表」不做。
2. **文件名**：`{中文表名}_{英文表名}.xlsx`。
3. **三类规则状态列**：不加，只导字段四列。
